## Notes

Researcher takeaways (not raw evidence):

- Zapier markets **Agents / AI teammates** (and a Chrome
  extension) but this first success was a **Zap**: trigger →
  AI step → action. Agent is a card on Home, not the object
  that got published.
- Copilot clarifies the spec before filling the canvas
  (source, output, Slack trigger shape, model). Contrast:
  Notion builds then you edit; Viktor takes the outcome and
  proposes a plan.
- Workflow-builder DNA is the product: Setup / Configure /
  Test on each step, Test run, Publish, Zap history, v1.
  Zapier seems to believe users still want that explicit
  graph, and AI should make selected parts of it adaptive
  rather than replacing the workflow abstraction.
- Awkward seam: Copilot wrote the prompt and schema, then
  told the user to paste them. It did not apply them.
- Tools/connections are late (Sign in when a step needs
  them), not a "connect 5 integrations" gate.
- HITL is an optional **step** after AI, not a per-write
  modal like Notion Mail / Viktor Approve.
- Zap history empty right after publish — tests may not
  write Zap runs, or history lags. Not verified.
- Independently triggered **Zapier Agent** vs this Zap was
  not built. MCP (external agent + Zapier tools) also
  unopened beyond the picker.

Follow-ups:

- Create an Agent from **Create your first agent** and
  compare to this Zap (activity tab, tools, trigger).
- Who can view/use/edit; whose credentials; admin app
  restrictions; sharing.
- Zap history after a real Slack push (not Copilot test).
- Whether Human in the Loop actually pauses the Zap.
- MCP: Claude/Cursor as the agent, Zapier as tools.
